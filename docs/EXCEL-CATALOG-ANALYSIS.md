# تحلیل کاتالوگ Excel محصولات قدیمی

**مأموریت:** PR-28A — فقط تحلیل و برنامه‌ریزی دسته‌ها

**فایل اعلام‌شده توسط مالک:**

```text
/home/radmansi/radman-deploy/products_20260821_182238.xlsx
```

**شیت:** `همه محصولات`

## وضعیت شواهد

اطلاعات زیر توسط مالک اعلام شده و باید با اجرای analyzer روی میزبان تأیید شود:

- ۳۲۳۲ محصول؛
- ۲۹ ستون؛
- ستون ۱: شناسه قدیمی؛
- ستون ۵: نام دسته اصلی؛
- ستون ۹: قیمت؛
- ستون ۱۲: موجود/ناموجود؛
- ستون ۱۳: فعال؛
- ستون ۲۲: وزن.

فایل خصوصی Excel در workspace این PR موجود نبود؛ بنابراین این سند **عدد یا نام دسته ساختگی ارائه نمی‌کند**. گزارش کامل واقعی، شامل همه نام‌های یکتای ستون ۵ و شمارش آن‌ها، با فرمان بخش بعد تولید می‌شود. انتظار تقریبی ۴۹ دسته و ۳۲۳۲ ردیف در خروجی با مقدار واقعی و اختلاف آن نمایش داده می‌شود.

## فرمان دقیق مالک

روی MizbanFa و از ریشه repository اجرا شود:

```bash
export RADMAN_PRIVATE_DIR=/home/radmansi/private
bash scripts/run_catalog_analysis.sh
```

runner فایل Excel را فقط می‌خواند، گزارش را روی stdout چاپ می‌کند و یک نسخه UTF-8 در مسیر زیر می‌گذارد:

```text
/home/radmansi/private/legacy-cache/catalog-analysis-<timestamp>.txt
```

برای مسیر یا نام شیت متفاوت:

```bash
bash scripts/run_catalog_analysis.sh \
  --excel /home/radmansi/radman-deploy/products_20260821_182238.xlsx \
  --sheet 'همه محصولات' \
  --private-dir /home/radmansi/private
```

پیش‌نیاز Python:

```bash
python3 -m pip install --user openpyxl
```

## ستون‌های تحلیل

| کاربرد | شماره ستون یک‌مبنا | مقدار پیش‌فرض analyzer |
|---|---:|---|
| شناسه قدیمی | ۱ | `COL_ID` |
| عنوان محصول برای نمونه‌های ID | تشخیص از header؛ fallback ستون ۲ | `COL_TITLE` |
| نام دسته اصلی | ۵ | `COL_CATEGORY` |
| قیمت | ۹ | `COL_PRICE` |
| موجودی متنی | ۱۲ | `COL_AVAILABILITY` |
| فعال | ۱۳ | `COL_ACTIVE` |
| وزن | ۲۲ | `COL_WEIGHT` |

analyzer ابتدا headerهای «عنوان محصول»، «نام محصول»، «عنوان کالا»، «نام کالا»، «عنوان» و «نام» را پیدا می‌کند و فقط در صورت نبود آن‌ها از ستون ۲ استفاده می‌کند. هر تشخیص متفاوت در هشدارها ثبت می‌شود و مالک باید پیش از اتکا به جدول نمونه‌های ID آن را تأیید کند. عنوان ستون ۵ نیز با «نام دسته اصلی» مقایسه می‌شود.

## گزارش کامل تولیدشده

### ۱. توزیع دسته‌ها

خروجی تمام مقادیر یکتای غیرخالی ستون ۵ را بدون حذف نمایش می‌دهد و بر اساس تعداد محصول نزولی مرتب می‌کند:

```text
رتبه | نام دقیق دسته قدیمی | تعداد محصول
```

همچنین موارد زیر را نشان می‌دهد:

- تعداد واقعی دسته‌های یکتا؛
- اختلاف با انتظار تقریبی ۴۹؛
- تعداد محصول بدون دسته؛
- نگاشت پیشنهادی تک‌تک دسته‌های قدیمی به taxonomy جدید.

### ۲. بازه ID و کنترل فرض جدید/قدیم

گزارش موارد زیر را چاپ می‌کند:

- کمینه ID؛
- بیشینه ID؛
- تعداد کل ردیف معتبر؛
- پنج محصول با پایین‌ترین ID؛
- پنج محصول با بالاترین ID؛
- ID، عنوان، قیمت و وزن هر نمونه.

> **فرض اعلام‌شده مالک:** ID پایین‌تر یعنی محصول جدیدتر؛ برای مثال ID 1 جدیدترین و ID 3643 قدیمی‌تر است. analyzer این فرض را از روی ID نتیجه‌گیری نمی‌کند؛ دو سر بازه را نمایش می‌دهد تا مالک با سایت قدیمی تأیید کند.

### ۳. پوشش وزن

مبنای coverage خواسته‌شده، غیرخالی بودن سلول ستون ۲۲ است:

- تعداد وزن غیرخالی؛
- تعداد وزن خالی؛
- درصد coverage؛
- تعداد وزن عددی معتبر؛
- تعداد سلول غیرخالی ولی غیرقابل‌تبدیل به عدد.

تفکیک دو شمارش آخر مانع از آن می‌شود که متن‌هایی مانند «نامشخص» به اشتباه وزن معتبر تلقی شوند.

### ۴. آمار قیمت و مقایسه دو سر ID

برای کل کاتالوگ:

- کمینه قیمت؛
- بیشینه قیمت؛
- میانگین قیمت؛
- تعداد قیمت معتبر و خالی/نامعتبر.

همین آمار همراه با پوشش وزن جداگانه برای این دو گروه محاسبه می‌شود:

1. ۱۰۰۰ محصول با پایین‌ترین ID — طبق فرض مالک، جدیدتر؛
2. ۱۰۰۰ محصول با بالاترین ID — طبق فرض مالک، قدیمی‌تر.

این مقایسه کمک می‌کند مشخص شود کدام سر کاتالوگ محصولات سبک‌تر یا ارزان‌تر دارد؛ نتیجه واقعی فقط پس از اجرای فایل خصوصی اعلام می‌شود.

### ۵. فعال و موجودی

- فعال: مقدار ستون ۱۳ برابر ۱؛
- غیرفعال: مقدار ستون ۱۳ برابر ۰؛
- مقدار فعال نامشخص؛
- `موجود` و `ناموجود` از ستون ۱۲؛
- جدول سایر مقادیر نرمال‌شده ستون ۱۲ برای کشف داده‌های غیرمنتظره.

## تحلیل pattern نام دسته

analyzer تعداد دسته و محصول منطبق با patternهای زیر را گزارش می‌کند. یک دسته ممکن است هم‌زمان در چند pattern باشد.

### سنگ و نگین

- عقیق
- فیروزه
- حدید
- در نجف
- یاقوت
- زمرد
- زبرجد
- اونیکس
- شرف‌الشمس
- نگین/سنگ

### مخاطب

- مردانه
- زنانه
- بچگانه
- اسپرت/مشترک

### سبک و ساخت

- خطی
- قلم‌زنی
- شبکه
- رکاب
- حرز
- دست‌ساز

## taxonomy پیشنهادی دو سطحی

قاعده پیشنهادی این است که category فقط نوع محصول و زیرنوع/مخاطب را نگه دارد. سنگ، سبک، خطی، رکاب و تکنیک ساخت به attribute/filter یا tag منتقل شوند؛ در نتیجه دسته‌های ترکیبی و تکراری کاهش می‌یابند.

```text
انگشتر
├── مردانه
├── زنانه
├── بچگانه
├── اسپرت/مشترک
└── عمومی/نیازمند تعیین

گردنبند و آویز
├── گردنبند
├── مدال و آویز
└── زنجیر

دستبند
├── مردانه
├── زنانه
├── بچگانه
├── اسپرت/مشترک
└── عمومی/نیازمند تعیین

گوشواره
├── زنانه
└── عمومی/نیازمند تعیین

ست و نیم‌ست
├── زنانه
└── عمومی/نیازمند تعیین

سنگ و نگین
├── عقیق
├── فیروزه
├── حدید
└── سایر سنگ‌ها

سایر/نیازمند بررسی
└── بررسی دستی
```

### attribute/filter پیشنهادی

- `pa_gemstone`: عقیق، فیروزه، حدید، در نجف، یاقوت، زمرد، زبرجد، اونیکس و غیره؛
- `pa_gender`: مردانه، زنانه، بچگانه، اسپرت/مشترک؛
- style/tag: خطی، قلم‌زنی، شبکه، رکاب، حرز، دست‌ساز.

گزارش runtime برای **همه دسته‌های واقعی** یک جدول زیر تولید می‌کند:

```text
دسته قدیمی | تعداد | سطح ۱ | سطح ۲ | attribute/tag پیشنهادی
```

این mapping پیشنهاد برنامه‌ریزی است و هیچ عملیات تغییر دسته یا import انجام نمی‌دهد.

## کنترل‌های ایمنی

- workbook با `read_only=True` و `data_only=True` باز می‌شود؛
- analyzer هیچ network client، image fetch، WP-CLI یا API import ندارد؛
- فایل Excel منبع هرگز output مجاز نیست و checksum آن در تست fixture ثابت می‌ماند؛
- runner مسیر `public_html` را رد می‌کند؛
- تنها mutation مجاز، نوشتن گزارش timestamped زیر `RADMAN_PRIVATE_DIR/legacy-cache` است؛
- هیچ WordPress، محصول، دسته، تصویر، موجودی یا قیمت تغییر نمی‌کند.
