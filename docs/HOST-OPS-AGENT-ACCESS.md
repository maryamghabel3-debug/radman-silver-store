## ۱. هدف (Purpose)

این سند، مسیر مصوب دسترسی عامل هوشمند به میزبان را تعریف می‌کند تا عملیات آتی استیجینگ (مانند ایمپورت صفحات استاتیک، پیکربندی افزونه‌های استیجینگ، تست‌های درگاه و کش) بدون نیاز به وارد کردن دستی ۲۰–۳۰ دستور WP-CLI توسط مالک انجام شود.

**اصول غیرقابل مصالحه:**
- هیچ رمز cPanel، هیچ رمز اصلی وردپرس، و هیچ رمز دیتابیس در اختیار عامل قرار نمی‌گیرد.
- دسترسی فقط به استیجینگ و در محدوده حساب کاربری cPanel (jail) مجاز است.
- هیچ کلید خصوصی یا توکنی در گیت کامیت نمی‌شود، در گزارشات چاپ نمی‌شود و در خروجی مأموریت بازگردانده نمی‌شود.
- تمامی تغییرات روی میزبان باید از طریق **رانرهای بازبینی‌شده (reviewed runners)** موجود در `scripts/` انجام شود که به‌صورت پیش‌فرض در حالت `--plan` اجرا می‌شوند.

---

## ۲. MODE A — پیشنهادی: دسترسی با SSH کلید عمومی (Public Key)

**مزیت اصلی:** بدون نیاز به به‌اشتراک‌گذاری رمز cPanel و بدون تعامل دستی در هر اجرا.

شرایط لازم:
1. عامل فقط در صورتی مجاز به تولید کلید است که **محل نگهداری دائمی و امن** برای کلید خصوصی در محیط اجرایی خود در دسترس داشته باشد (Persistent Private Secret Storage).
2. کلید اختصاصی برای این پروژه و با الگوریتم **Ed25519** تولید می‌شود.
3. نام کلید: `radman_staging_ops_20260812`.
4. کلید خصوصی:
   - فقط در حافظه/فضای امن عامل باقی می‌ماند.
   - دسترسی فایل `chmod 600`.
   - هرگز کامیت نمی‌شود، هرگز print نمی‌شود، هرگز در گزارش مأموریت بازگردانده نمی‌شود.
5. **فقط کلید عمومی و SHA256 fingerprint** به مالک تحویل داده می‌شود.
6. مالک صرفاً کلید عمومی را از طریق **cPanel → SSH Access → Manage SSH Keys → Import Key** وارد و Authorize می‌کند.
7. دسترسی فقط به حساب cPanel استیجینگ محدود می‌شود (jailed SSH) و به پروداکشن دستی وجود ندارد.
8. هر مأموریت که بخواهد روی میزبان تغییری اعمال کند، باید صریحاً از نوع Host Execution Mission باشد و رانرهای موجود در `scripts/radman_stage_apply.sh` را صدا بزند.

**اگر محیط عامل نگهداری دائمی امن برای کلید خصوصی نداشته باشد (وضعیت فعلی این sandbox):**
- تولید کلید ممنوع است.
- گزارش: `PERSISTENT SSH PRIVATE-KEY STORAGE NOT AVAILABLE`
- به سراغ **Mode B** می‌رویم.

## ۳. MODE B — Fallback: Application Password وردپرس + رانر تک‌دستور

در این حالت:
1. یک **کاربر وردپرس اختصاصی اتوماسیون** (مثلاً `radman-automation`) با نقش حداقلی لازم (Editor یا Shop Manager محدود) ایجاد می‌شود.
2. یک **WordPress Application Password** یک‌بارمصرف و قابل ابطال برای این کاربر ساخته می‌شود.
3. رمز ورود عادی وردپرس هیچ‌گاه در اختیار عامل قرار نمی‌گیرد.
4. دسترسی REST فقط برای عملیات محتوایی/رسانه‌ای تأییدشده (افزودن/به‌روزرسانی صفحات Draft، آپلود رسانه) استفاده می‌شود.
5. **تغییرات پوسته/فایل‌سیستم/WP-CLI فقط از طریق رانر تک‌دستور** (`scripts/radman_stage_apply.sh`) اعمال می‌شوند؛ مالک پس از تأیید ریویو، فقط یک دستور اجرا می‌کند.
6. Application Password در فایل خصوصی خارج از وب‌روت (مثلاً `/home/radmansi/.config/radman/staging.env` با `chmod 600`) ذخیره می‌شود، نه در گیت.

## ۴. نتیجه تشخیص در این مأموریت (2026-08-12)

**وضعیت محیط اجرای عامل (sandbox):**
- هیچ `~/.ssh/` از قبل وجود ندارد.
- هیچ Persistent Secret Storage در این سشن تضمین‌شده نیست (فایل‌های داخل `/home/user` snapshot می‌شوند اما کلید خصوصی نباید در یک snapshot قابل‌مشاهده/قابل بازیافت قرار گیرد).
- بنابراین طبق قاعده‌ی امنیتی Mode A:

**`PERSISTENT SSH PRIVATE-KEY STORAGE NOT AVAILABLE`**

در نتیجه در این مأموریت کلید SSH تولید نمی‌شود. هرگاه میزبان اجرای دائمی عامل (`agents/` runtime) روی سرور میزبان‌فا در یک مأموریت آتی مصوب مستقر شد و توانست کلید خصوصی را در `RADMAN_PRIVATE_DIR/ssh/` با `chmod 600` نگهداری کند، می‌توان با یک مأموریت مجزا کلید Ed25519 تولید و عمومی آن را برای import به مالک تحویل داد.

## ۵. فرم تحویل کلید عمومی (برای مأموریت آتی)

وقتی Mode A در مأموریتی مصوب فعال شد، خروجی مأموریت دقیقاً شامل موارد زیر خواهد بود (و نه چیز دیگر):

- **عنوان مأموریت**
- **Public Key** (متن کامل `ssh-ed25519 AAAA... radman_staging_ops_20260812`)
- **SHA256 Fingerprint** (خروجی `ssh-keygen -lf`)
- **تأیید صریح:**
  - «Private key is stored persistently and securely with chmod 600.»
  - «Private key was not printed, not committed, and not returned in this report.»
- **دستورالعمل برای مالک:** وارد کردن کلید عمومی در cPanel → SSH Access → Authorize.
