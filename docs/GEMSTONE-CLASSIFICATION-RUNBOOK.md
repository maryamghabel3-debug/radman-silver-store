# راهنمای طبقه‌بندی محافظه‌کارانه نگین برای قیمت‌گذاری

**بازبینی و نرخ موقت مالک:** `2026-08-21, Asia/Tehran`
**ابزار:** `agents/agent_gemstone_classifier.py`

## دامنه

classifier فقط برای `rings` یکی از چهار کلاس زیر را برمی‌گرداند:

- `no_stone`
- `small_stone`
- `large_stone`
- `uncertain`

برای گردنبند و دستبند، طبقه‌بندی نرخ نگین کاربرد ندارد و همیشه نرخ محافظه‌کارانه عمومی اعمال می‌شود.

## ترتیب شواهد

1. عنوان، توضیح کوتاه و توضیح کامل normalize می‌شوند.
2. عبارت صریح مانند «بدون نگین»، «نگین ریز» یا «نگین درشت» بررسی می‌شود.
3. اگر متن فقط نام نگین/سنگ را ذکر کند ولی اندازه را ثابت نکند، نتیجه `uncertain` است.
4. تعارض عبارتی نیز `uncertain` می‌شود.
5. فقط وقتی متن نتیجه‌ای ندارد، heuristic قطعی و چندتصویری اجرا می‌شود.

شواهد تصویری دنبال candidate رنگیِ موضعی در مرکز است. حداقل دو view مستقل و توافق حداقل دوسوم لازم است. این heuristic هیچ تصویری را تغییر نمی‌دهد.

## قانون confidence

نرخ پایین‌تر `590000` تومان/گرم تنها برای حلقه‌ای مجاز است که:

```text
stone_class == large_stone AND confidence >= 0.85
```

هر confidence پایین‌تر، تناقض، متن کلی، یک تصویر، تصویر ناخوانا یا ابهام به `uncertain` تنزل می‌یابد، نرخ `650000` می‌گیرد و برای review علامت می‌خورد. classifier اجازه ندارد صرفاً برای کاهش قیمت، وجود نگین درشت را حدس بزند.

## اجرای مستقل

ورودی JSON باید list یا شیئی با کلید `products` باشد و می‌تواند `original_image_paths` داشته باشد:

```sh
python3 agents/agent_gemstone_classifier.py \
  --input /private/path/products.json \
  --output /private/path/gemstone-classification.json
```

خروجی برای هر محصول `stone_class`، `confidence`، `source`، `requires_review`، evidence متنی و evidence هر تصویر را ثبت می‌کند.

## چک‌لیست بازبینی

- آیا محصول واقعاً انگشتر است؟
- آیا متن legacy اندازه را صریح می‌گوید یا فقط نام سنگ را؟
- آیا چند عکس همان سنگ مرکزی را نشان می‌دهند؟
- آیا رنگ اشباع‌شده ناشی از پوست/پس‌زمینه است؟
- آیا confidence برای `large_stone` حداقل `0.85` است؟
- در هر ابهام: `uncertain` + نرخ `650000` + review.
